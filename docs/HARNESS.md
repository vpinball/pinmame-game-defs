# Harness and reverse engineering

On-demand companion to `docs/INSTRUCTIONS.md`. Read it before designing or running any LibPinMAME harness scenario, and before escalating to Ghidra; it is not loaded by default.
The runbook wins where the two disagree.

**Belongs here:** how to write, run and retain harness scenarios, how to read their traces as evidence, platform boot and service recipes, and the Ghidra escalation.

**Does not belong here:** the harness non-negotiables every session needs (`docs/INSTRUCTIONS.md`), or one machine's runs (its knowledge note and `evidence/runtime/`).

## Rules

Use the implemented LibPinMAME gameplay harness for unresolved runtime behavior: boot a legal user-supplied ROM, drive switches, capture lamps/solenoids/displays, preserve NVRAM/reset conditions, and produce content-addressed traces without ROM bytes. Define explicit scenarios and expected causal transitions instead of free-play logs.

Write repeatable action sequences as `pinmame-harness-scenario` JSON validated by `schemas/harness-scenario.schema.json`, retain reusable scenarios under `tools/harness-scenarios/`, and invoke them with `python tools/run_pinmame_harness.py --library <libpinmame> --game <driver> --rom-path <read-only-rom-root> --work-dir <new-isolated-state> --scenario <scenario.json> --output <external-run.json>`. The runner supports direct switch pulses and states, named keyboard inputs, waits, display-driven navigation, output-driven navigation, and output waits. Use named service keys when the emulator input port implements momentary or toggled cabinet behavior; a persistent `set_switch` is not necessarily equivalent to a real service-button edge.

Named key actions enable PinMAME keyboard handling for the entire run. Do not mix them with direct switch actions in a driver-owned cabinet or keyboard-backed matrix range: a driver's `SWITCH_UPDATE` callback may overwrite those direct states. On Pinball 2000, PinMAME revisions before b7a60eb0 refreshed the per-game optos to their raw inactive `1` every frame, so an `active_state: 0` pulse in a trace recorded on such a revision could be overwritten between harness writes and is not polarity evidence. From b7a60eb0 the optos are declared in `coreGlobals.invSw`, publish active-high like every other P2K switch (`1` = beam blocked), and are no longer refreshed; but while the `balls_in_trough` toggle is on, `SWITCH_UPDATE(p2k)` rewrites trough optos 42-45 to occupied every frame, and with keyboard handling on it also rewrites the coin, cabinet, diagnostic, Start and Launch inputs. Use the platform's named keyboard input, such as `balls_in_trough`, when it owns the intended cabinet stimulus. On a driver with `simData`, keyboard handling also activates PinMAME's built-in simulator and can contaminate the trace with simulated switch activity; use named keys there only when that simulator behavior is deliberate and explicitly accounted for in the evidence.

Treat each driver's input-port declaration as authoritative for cabinet-button behavior. In the Data East alpha path, `DE_COMPORTS` declares the Green service input as toggled while `DE_COMPORTS2` declares it momentary; a scenario label and action sequence must match the selected driver rather than calling every service key momentary. With the default `sequential` switch converter the harness rejects public switch addresses outside `-7..120` before entering LibPinMAME because PinMAME's native switch getters/setters do not bounds-check the converted matrix index. The one exception is a scenario that declares `"switch_converter": "gts3"`: it admits only `gts3_sw2m`'s valid numbers (-8 to -1, and 0-147 with a last digit of 0-7) and touches no switch until `PinmameGetHardwareGen()` reports GTS3. Do not widen either envelope until the harness can inspect the selected driver's address converter or LibPinMAME provides a checked API.

A WPC ROM's own switch-edges test settles which public level the ROM treats as active for an address the emulator does not normalize. Set each public level separately and hold it for a couple of seconds, with a normalized opto and an ordinary switch in the same run as controls: the switch's name appears on the top display line after the edge the ROM treats as active and is gone after the release edge. The switch-levels grid shows raw matrix levels and only restates the mask. Together with the inversion mask and the platform read path, that active level fixes `physical.normally_closed` as `docs/PLATFORMS.md` describes; it does not say which physical event (a blocked or a clear beam) the ROM calls active. On WPC-Fliptronic and later ROMs the top display line reports the ROM's logical state while the switch grid on the left shows raw matrix closures, so read the top line and include a same-generation masked opto as a control.

Never hard-code diagnostic page counts when the ROM can expose a display or output checkpoint. `pulse_until_display` polls throughout the full settle window so it can catch short-lived titles; after detecting a transient test title, use `wait_until_output` to prove the test became active without sending another input that could skip past it. `pulse_until_output` is appropriate only when every additional pulse is safe until the requested transition occurs. Include localized display targets where supported firmware can change language, and fail the run if the expected checkpoint never appears.

Start every evidentiary run with a newly created state directory and a deliberate boot-stabilization interval. Some generations do not reach attract mode on their first power-up from empty CMOS (Williams System 3-7 stop on the game-identification screen); initialize such a state directory with exactly one retained, hashed boot scenario and cite that initialization run beside the evidentiary one. Never reuse NVRAM from exploratory attempts as though it were a clean run. Retain the complete raw JSON, scenario SHA-256, exact LibPinMAME revision and binary SHA-256, ROM archive SHA-256, command template, service language, and a canonical external-directory manifest under the working root. Commit only compact derived evidence and hashes. A transition proves that a public address changed under the recorded conditions; it does not alone prove physical identity, polarity, quantity, or socket location, and failure to observe an address is never proof that it is unused.

When a scenario fails after the ROM starts, the harness still writes a nonzero-exit partial trace containing completed steps, recorded events, a failure block, and a final failure snapshot. Preserve that artifact while correcting the scenario; it is diagnostic evidence, but it is not a successful evidentiary run and must not be cited as one.

A motorized mechanism whose only feedback is a switch the motor itself moves cannot be exercised by a static scenario, because the switch must answer the ROM's own motor outputs. Probe it with a reactive host model instead:

1. Integrate the mechanism's position from the public motor and direction outputs.
2. Write the feedback switch from an explicitly named candidate pattern.
3. Drive the ROM's own mechanism service tests, and record the modelled position at every motor stop and actuator pulse.

Run more than one candidate pattern and more than one starting position. Behaviour that is identical across them is the ROM's contract. Behaviour that changes with the starting position suggests the ROM tracks position relative to remembered state rather than an absolute sensor mark; confirm it by also varying the stored state (NVRAM) before claiming memory-based tracking. A pattern the ROM accepts is still a synthetic probe, never a measurement of the physical cam.

When the ROM's service tests display device names, dump them across the switch, lamp, solenoid, and flasher tests: they are machine evidence for labels and orderings. Decode every display attribute bit (for example an alphanumeric period) instead of dropping unknown segment values.

Ghidra is escalation-only rather than part of every game's startup check. When a game reaches the Ghidra escalation described later, [download Ghidra from the NSA project](https://github.com/NationalSecurityAgency/ghidra/releases), verify it launches, and stop that game if it is unavailable; do not replace reverse engineering with speculation.

Escalate to Ghidra only for authoring-critical facts still unresolved after manual, VPX script, PinMAME source, ROM strings/data tables, and harness traces. Follow the approach used in the `kiki` project, normally discovered as a sibling of this repository: identify the exact ROM, loader/CPU memory map, entry points, I/O tables, state variables, and mechanism routines; document addresses and confidence; confirm static conclusions with runtime traces when possible. Do not promote speculative decompilation labels to validated physical facts.

## Lessons

Each lesson ends with the lines of `docs/archive/current-state-ledger-until-2026-10-01.md` that
record the case behind it, and with `verified:` where it was checked against the repository code or
pinned PinMAME source on 2026-10-01. A lesson added later names the commit or knowledge note that
produced it instead.

- **Match the mechanics mask to the question.** `--handle-mechanics` defaults to 0, as LibPinMAME does. Bit N runs the driver's built-in `mech_add` slot N (slots 0-4); `hw.handleMech` runs whenever the mask is non-zero, tests its own bits, and can do more than move mechanism switches: copy cabinet inputs into the matrix (Johnny Mnemonic 116->67, 118->68) or time a custom solenoid (The Shadow's 51 needs bit 1). Use the known-working table's `Controller.HandleMechanics` for mechanism-feedback runs, use 0 for polarity probes on switches `handleMech` overwrites, and record which bit a channel needs before calling it live or dead. (archive L333, L394, L449, L662, L808, L842; verified: `run_pinmame_harness.py --handle-mechanics`, `core.c core_updateSw`, `mech.c mech_updateAll`, `jm.c`, `ts.c`)
- **Forced physical outputs are sampled once per poll.** Capcom and SAM force physical output, which LibPinMAME integrates only when a solenoid query such as `PinmameGetChangedSolenoids` runs; the runner now calls it every poll (about 10 ms), so shorter pulses can still be missed. Traces recorded before that call under-report solenoids: never read their negatives as absence. (archive L403; verified: `_poll_outputs`, `libpinmame.cpp`, `capcom.c`, `sam.c`)
- **Record the output mode.** Other drivers run in the default binary mode, where an auxiliary-board address can differ from physical mode: on the Whitestar double-magnet board, 35 is aux latch bit 2 in binary mode but the processor-reset strobe in physical mode, and 36 exists only in binary mode. (archive L317; verified: `se.c` 520-5143-00 branch)
- **Change one input per poll.** A response to two inputs changed together is unattributable: add one isolation run per input and a no-change control. If a modelled run seems to show a threshold, add a pair of runs that separates it from an edge rule. Word the result "consistent with", not "proven". (archive L318, L323, L583)
- **More polarity oracles.** Hold a home switch at each level from power-up and watch the motor search; hold a target bank at each level and count reset-coil retries; read a power-up troubleshooting list of switches whose level differs from the expected rest (Capcom C5 INFO; it covers only the switches it checks); hold every candidate during a stuck-switch search and let the ROM report each address (BY35). (archive L319, L409, L584, L859)
- **Decode ROM name tables across the driver family.** `tools/s11_rom_name_tables.py` and `tools/capcom_kingpin_rom_records.py` read the service text statically; pair each table with a runtime walk before binding addresses. A prototype ROM can name hardware that production prints UNUSED, and production firmware can still drive it. (archive L399, L582, L583)
- **Test order can place emitters.** The manual's lamp-test text (start lamp, step direction) plus the ROM's observed test order places lamps that no drawing numbers. (archive L552)
- **Pair displayed names with the address that changed.** Test-menu numbers are ROM selector numbers, not public addresses (`AUX #33` is not public 33), and a press count drifts from them after a skipped optional item. Navigate with the inputs PinMAME copies from, not the matrix addresses it overwrites, or presses double-register. (archive L404, L407, L1104)
- **Prove a `FLIP_SWNO` copy through the button bit.** A `pulse` hold rewrites its switch every poll and masks `core_updateSw`'s per-frame overwrite of the target; `set_switch` and `--initial-switch` write once. (archive L297, L407; verified: `_hold_switch`, `set_switch`)
- **Boot and service recipes.** Fresh WPC NVRAM stops on FACTORY SETTINGS RESTORED: WPC-95 cleared with Escape (5), World Cup Soccer with Begin Test (8) once and Escape three times. WPC-95 service buttons need the coin door open (22 released). A non-empty power-up report adds screens, so enable the mechanisms it checks and count menu presses from an exploratory run. System 11B: with -6 = 0, Advance twice (Game ID, Ad 70), set -6 = 1 and Advance once for Game-Over; set Auto Burn-in to YES with Credit, then -6 = 1 and Advance, for a coil test that names every step (tried on `GEN_S11B` only). BY35 ignores Self Test (-7) until the power-up test ends (about 18 s on Fathom). SAM needs `--ready-timeout` well above 10 s. (archive L395, L476, L496, L577-L581, L808, L912)
- **Ready means state 1.** Since PinMAME b7a60eb0 `PinmameRun` reports emulator state 2 (starting) before 1 (running), and the output getters dereference the not-yet-initialized core while it is 2, so the runner treats only 1 as ready; the same revision hands Pinball 2000 and the pinHeck colour displays to `OnDisplayUpdated` as depth-16 5.6.5 frames, which the runner widens to rgb24. (2026-10-05 PinMAME pin bump commit)
- **pinHeck boots in stages and its menus name everything.** Domino's, Rob Zombie's Spookshow and The Jetsons program their flash and AV EEPROM from the romset on an empty NVRAM (about eight emulated minutes) and then ask for a restart twice, so seed each evidence run with a retained copy of the post-update NVRAM and say so; America's Most Haunted boots at once. Enter (6) opens the operator menu, the right flipper button (112) steps and Back (5) leaves; the Switch Edge test draws every closure in a grid laid out like the factory chart, the Solenoid test names each coil and fires it on Enter, and the Lamp test names every GI output and lamp while lighting only it. The menu order differs per firmware. (knowledge/spooky-pinball/*.md, tools/pinheck_harness_scenarios.py)
- **Check ROM bytes, not zip names.** A library zip can hold a differently built dump; compare member sizes and SHA-1 with the pinned driver before citing a run. (archive L492)
- **`import-legacy` is one-shot.** It rewrites every migrated machine and knowledge file from `games/*.json`, duplicating IDs over curated records, resetting coverage and stamping HEAD as the legacy revision. Some conflicts are written by a `*_spatial.py` curator; find what writes `definition["conflicts"]` first. (archive L1068, L1070; verified: `legacy.py import_legacy_definitions`)
- **Find ROM text tables by anchor, in every set.** On Williams System 11B the service-text tables can live in the U27 program ROM rather than U26. Locate each table by its anchor text in every loadable set (`tools/bk2k_rom_name_tables.py`), never by an offset carried over from another game. (archive L357)
- **Sweep every public address with a same-run control.** One Switch Levels and Switch Edges sweep across the whole public range settles the matrix contract: which addresses the ROM names, which it scans without a name, which it ignores, and which the emulator overwrites. (archive L358)
- **Hold System 11B Auto-Up/Manual-Down (-6) at 1** for any game-phase or power-up probe. At the harness default of 0 the ROM restarted into FACTORY SETTING anywhere from a fraction of a second to about half a minute after Start. (archive L359)
- **Number tests from the ROM.** A ROM can carry a service test its manual does not describe, so take each test's number and name from the ROM's own display. (archive L360)
- **An initialized NVRAM also lifts the System 11 FACTORY SETTING stop.** A first 30 s run from empty NVRAM writes the `.nv` file; a second run from a fresh state directory holding only that file boots into attract mode and accepts coins and Credit (`diner_l4`, System 11C; `eatpm_l4`, System 11B). Retain the initialization run beside the evidentiary one and cite the `.nv` hash in its `nvram_initialization`. (commit "defs: settle Diner solenoid 23 from a gameplay run"; Elvira knowledge note)
- **Output checkpoints accept either direction.** `pulse_until_output`, and `wait_until_output` without `active_only`, pass on any transition at the address, and `active_only` asks only for some nonzero state among them. Use them so a run fails when the game or menu does not progress, and read each transition's direction from the trace in the evidence test. (commit "defs: state that Diner's checkpoints accept either direction")
- **Repeat-mode tests blink, and their first item varies.** WPC T.5 FLASHER TEST and the DMD test menus blink the selected name: take several frames 0.25 s apart and checkpoint the selected output. Doctor Who's T.5 starts at solenoid 6 and steps 6, 8, 14, 17-24, so a checkpoint copied from a game that starts at 17 fails. (commit "defs: settle Doctor Who solenoid 19 from the ROM's flasher test")
- **Gameplay can identify a playfield switch.** On BY35, a closure that completes a drop bank fires that bank's reset coil, or lights an award no other member's closure lit, and a tilt drops the flipper-enable relay (19). That settled switch 2 on Harlem Globetrotters On Tour and Skateball against the platform's Ball Roll Tilt. Decode the seven-segment score with the comma bit (0x80) masked. On Beat the Clock (`by6803`) a target held through a ball serve drew no second bank-reset pulse (an exploratory run in the working root's `review-artifacts/beat-the-clock-1985/harness/held-target-across-serve-2026-10-01`), but completing the bank with each candidate closed last pays a bonus and a lamp show both times. (commits "defs: settle Harlem Globetrotters switch 2 from a gameplay run", "defs: settle Skateball switch 2 and solenoid 19 from a gameplay run", "defs: settle Beat the Clock switches 2, 7 and 16 from a gameplay run")
- **A motor drive may need the game's own mechanism test.** Red and Ted's Road Show's T.4 and T.5 skip its motor drives 17-20, while its T.17 "TED" TEST runs by itself, names each step and raises the mouth-motor direction (19) with the motor (20) only in MOUTH OPEN. Other games differ: Terminator 2's T.4 names and pulses its gun motor (11). (commit "defs: settle Road Show solenoid 19 from the ROM's Ted test")
- **Bally 6803 alphanumeric service tests name switches and drivers.** Special Force's Switch Test names every closed switch, and its Solenoid Test fires one driver at a time with its name, transistor and connector, continuous outputs included (public 19 is FLIPPER, Q07). Holding a keypad-parallel switch such as public 2 while pressing Test (-7) opens the Switch Test directly through the stuck-switch check. The Solenoid Test ignores Test and some Enter presses while it cycles, so run the two tests from separate fresh states. The harness's 16-segment table does not decode `CORE_SEG98`; decode the raw segments afterwards with the glyph table in `tests/test_settle_legacy_label_conflicts.py`. Special Force counted coins but never started a game from fresh NVRAM, for a reason not found (diagnostic runs in the working root's `review-artifacts/special-force-1986/harness/no-game-start-2026-10-01`); its service tests did not need one. (commit "defs: settle Special Force's legacy conflicts from its service tests")
- **Stern MPU-200 tests and probes.** The ROM ignores the self-test button (-7) until about 18 s after boot, so boot-wait 20 s. Press 1 runs the burn-in (every output in turn, repeating), press 4 the solenoid test (each coil pulsed with its driver-position number on player display 0, read 0.25 s after the pulse because the display is multiplexed) and press 5 the switch test (closing public N shows N, and the display flashes 0 with everything open). Gameplay needs only direct switch writes: coin on a chute (1), start (6) with the ball held on the outhole switch (33) so the ROM kicks it, then release 33. One closure at a time identifies a coil (a bumper or sling switch fires its own coil; completing a drop bank fires its reset), and the lamp that flashes for a closure identifies a sign or value lamp. The vari-value lamp sweep and a tilt (public 7 drops the flipper-enable relay, 19) are visible in an idle run. (commit "defs: curate Star Gazer"; scenarios in `tools/harness-scenarios/by35/stargzr-*.json`)
- **A serve can wait for the player.** Spectrum (BY35) kicks its drain saucer once when switch 8 rises. With the ball left on 8 it kicks again just after the right flipper button (public 1) rises, or on its own about 24 s after the first kick; with 8 held from power-up it kicked nothing in the 15 s after the start. Look for a launch input before calling a serve missing. (commit "defs: settle Spectrum switches 2 and 7 from a gameplay run"; exploratory runs in the working root's `review-artifacts/spectrum-1981/harness/serve-exploration-2026-10-01`)
- **Quicksilver's Stern MPU-200 scenarios.** After the ROM's power-up test (about 25 s on Quicksilver) one Self Test press (public -7) starts the burn-in, which cycles every output (a looping 19-step solenoid sequence with the lamps flashing), and five presses reach the stuck-switch display, which shows the closed address's own number on the Player Score displays: close each matrix address alone for three seconds. Coins on the chute switches add credits, the credit button starts a game from credits, and the game does not leave the serve until the out-hole switch is released (otherwise the out-hole and drop-bank resets repeat forever). With a game running, closing a bumper or slingshot switch fires its own coil, closing the last target of a bank fires that bank's reset, and a tilt drops the flipper-enable relay (19). (commit "defs: curate Stern Quicksilver (1980)"; scenarios `tools/harness-scenarios/stern/quicksilver-*.json`)
- **Williams System 7 service walk and drop targets.** From attract mode, Manual-Down (`-6` = 0) and Advance (`-7`) enter the display digits test; with Auto-Up (`-6` = 1) each Advance steps to Test 00 (sound), 01 (lamps), 02 (solenoids) and 03 (switches), shown in the credit display, while Advance with Manual-Down only steps inside a test. In Test 02 set Manual-Down right after entering: each Advance then holds one step, the ball-in-play display shows its number and the ROM pulses that public solenoid, so number and address pair directly. In Test 03 the ball-in-play display shows each closed switch's number. In play, hold a drop-target bank's three switches closed until its reset fires and release them afterwards: real drop targets stay down, and momentary pulses never complete a bank, they only let its timer expire into a reset. Ball-ramp and lock switches likewise stay closed while a ball rests on them; a lock release that should fire with the balls in place needs a `wait_until_output` before the switches open. (knowledge note `knowledge/williams/black-knight-1980.md`; scenarios `tools/harness-scenarios/system-7/black-knight-*.json`)
- **Data East DMD service tests name every switch, lamp and coil, but a DMD needs a title adapter and a title checkpoint.** The generic harness cannot read a dot-matrix display, so `pulse_until_display` never matches; `tools/tftc_harness.py` is the pattern: compare the rows a title occupies (a 7-row band) against retained, visually read frames and return empty text for anything else. Reach each test by its title, not by counting presses: two otherwise identical `tftc_303` runs landed one test apart. Drive everything with direct public writes (`-7` pulses for the Black Advance button, `-6` held at 1 for the Reverse walk into Diagnostics, `3` for Start) so keyboard handling stays off and 1-8 and 62-64 stay reachable. On `tftc_303` the Active Switch Test shows the ROM's name, its two wire colours and `#nn` for any public switch held at 1 and NONE with all at 0; the discrete Lamp Test steps one lamp per Start press (a 300 ms hold repeats the step, 120 ms does not) and prints name, wires and `#nn`; the automatic Cycling Coils test fires public 1-22 in order, with the relay at 10 and a flash lamp 25-32 after each of drives 1-8, and prints `COIL:`, `RELAY:` or `FL:` names; the Laser Kick Test needs about six seconds before its first closure and then fires 22, 6, 7 and 5 from switches 17, 38, 52 and 55; Adjustment 61 (`PRINTER INTERFACE`, reached by stepping backwards from the audits) asserts the printer lines on Start. Read the frames at 3x, pair each reading with its pixel digest, pin those digests in the reader so a rerun whose frames differ is refused rather than relabelled, and make every title target exactly one template that no other title contains, since the harness matches targets as substrings (`SWITCH TEST` is inside `ACTIVE SWITCH TEST`). A game start from fresh NVRAM also works with direct writes: with balls on 9-14, two coins on 6 and Start (3) make the ROM feed and serve the trough, and it waits for the host to move each ball. (commits "defs: curate Tales from the Crypt from its manual, service tests and retained table" and "defs: apply the Tales from the Crypt review findings")
- **WPC-95 menus shift when a mechanism is enabled, and T.1 can fire coils.** With PinMAME's built-in mechanism answering, a WPC-95 ROM finds nothing to report at power-up, so one fewer Enter reaches the main menu (NBA Fastbreak: two with `--handle-mechanics 1`, three without); read the frames before trusting a press count. Inside T.1 SWITCH EDGES the ROM still fires a jet or sling coil for its own switch and a flipper for its button, which pairs each switch with its coil in the same sweep. Names in T.4/T.5 blink: take several frames 0.25 s apart where both phases came out dark. (commit "defs: curate NBA Fastbreak from its manual, service tests and retained table")
- **A Data East DMD ROM's tests differ per game; walk them before scripting.** Tommy (US 4.00) has no Laser Kick test but a Mirror test and an Arch (blinder) test, and its COIL TEST is a selector: the right flipper button (public 82) steps forward, the left (84) back, and Start fires the shown entry, which prints each drive's name, wires and printed number (`#1L`, `#4R`, `#09`) where Cycling Coils prints only the name. In its single-lamp LAMP TEST a 120 ms Start press occasionally stepped two lamps, so the lamp in between lit for about 150 ms and no snapshot caught it; a 60 ms press stepped once every time. Check each press's lamp transitions, not only the settled snapshot, before concluding that a test skips an address. Pressing Start on its PRINTER INTERFACE adjustment wrote nothing to the CN3 lines. Use `cols` in a title template when a screen's state column shares the title's rows. (commit "defs: curate The Who's Tommy Pinball Wizard from its manual, service tests and retained table")
- **Gottlieb System 3 DMD service tests name everything; drive them through the `gts3` switch converter.** System 3 numbers switches in Gottlieb's decimal notation and keeps the flipper buttons at 141 (right) and 143 (left), so a scenario sets `"switch_converter": "gts3"`; the harness then admits -8 to -1 and 0-147 with a last digit of 0-7 and refuses to touch a switch until `PinmameGetHardwareGen()` reports GTS3. Stargate's first power-up from empty NVRAM shows REPLAY AT 00 and accepts no credit: initialize with Test (-8) twice, the left flipper three times to GAME ADJUSTMENTS, the right flipper, and the credit button twice (CREDIT BUTTON LOADS FACTORY SETTINGS, then ... LOADS ENGLISH). In the menu the left flipper steps, the right flipper selects and Test steps to the next self-test, but Test is ignored while SELF-TEST 1 MEMORY TEST runs (wait 12 s). The Lamp Matrix Test blinks one lamp per step, the Relay & Solenoid and Aux Driver tests fire the shown driver on the credit button (4) and display it from 0, and the Switch Edges Test names whatever address changed last but keeps it on screen after release, so it names devices without proving a level. PinMAME smooths System 3 solenoids over four frames, so pulse a CPU-fired switch several times before reading a missing coil as absent. The harness cannot read a DMD; `tools/gts3_dmd_text.py` reads the saved frames glyph by glyph against a committed table. (knowledge note `knowledge/gottlieb/stargate-1995.md`; scenarios `tools/harness-scenarios/gts3/stargate-*.json`)
- **A motor test that stops on an end switch is a polarity oracle, and a hybrid WPC-95 ROM may show no power-up report.** Jack•Bot's T.17 VISOR TEST runs one motor output (28) until the selected end switch reads closed: with the host holding the other switch at 1 the motor keeps running, with the selected one at 1 it stops at once and restarts on release, which pins each switch's active level and role in one run (`jb-visor-test.json`). T.16 RAMP TEST cycles its two coils regardless of the ramp switch but prints RAMP DOWN SW. while it reads 15 closed. The `GEN_WPC95DCS` ROM showed no power-up report with no mechanism answering (two Enters reach the main menu), and its T.5 starts at solenoid 15, so a checkpoint that waits for 17 fails. - **Safe Cracker's tests name the backbox lamp board and every mechanism.** Two Enters after Escape reach its MAIN MENU (no power-up report). T.8 SINGLE LAMPS walks 11-88 and then the auxiliary columns 91-148, printing those as the 48 Lamp & Driver board's `L24`-`L1` and `L48`-`L25` with each lamp's power wire, so the ROM itself pairs a `lampCol` board's bits with its lamps. T.16-T.20 (MOVING TGT., TOKEN TEST, LIGHT ROPE, DROP TARGET, TOP TROUGH) show each mechanism's switches by number and fire its coil on Enter or while a switch is held; T.17 ignores a press that arrives during a dispense, and T.20's switch boxes latch after release, so read its coils from the transitions. Names blink in T.4, T.5, T.8 and T.12: take three or four frames per item and pin the brightest. (knowledge note `knowledge/bally/safe-cracker-1996.md`; scenarios `tools/harness-scenarios/wpc-95/sc-*.json`)
