Williams Medieval Madness (`williams.medieval-madness.1997`) was promoted on 2026-08-05 and is the first author-ready Williams WPC machine. It introduced the `pinmame.wpc-95` controller profile, which every later WPC-95 game should reuse instead of `pinmame.wpc-alpha`.

Bally Attack From Mars (`bally.attack-from-mars.1995`) was promoted on 2026-08-05 as the second WPC-95 machine, incorporating and superseding external PR #2. It is the first definition to enumerate PinMAME's two auxiliary lamp columns: `afmGameData` declares `lampCol = 2`, and the sixteen saucer-L.E.D. addresses 91-98 and 101-108 are shifted in serially by public solenoids 37 and 38. Reuse that pattern for any other game whose `core_tGameData` declares extra lamp columns, and note that WPC-95 auxiliary outputs 37-40 are mirrored at 41-44 while `custSol` duplicates appear from 51 upward. Its curation also recorded a genuine pinned-PinMAME defect worth remembering: `afm.c` names the two loop gates the opposite way round from the manual and from both retained known-working scripts, and is internally inconsistent because its `/* 33 */` and `/* 34 */` comments contradict its own `WPC_FLIPPERCOIL95` bit reads. Verify emulator-side left/right naming against the printed table before trusting it.

Bally Centaur (`bally.centaur.1981`) is claimed as maintainer-local pending work on branch `centaur-1981`. It is complete except for one thing and remains `partial` only because of it.

Done and validated: identity and the three-driver family, the full 48-position switch matrix with per-switch polarity and construction, all 32 MPU option switches, twenty-one solenoid outputs, seventy-one of seventy-six lamps named from the schematic, six `dispBy7` displays, ten mechanisms, driver variant differences, and spatial records for every one of the 182 devices.

The single blocker is that **five auxiliary outputs - public 68, 84, 100, 113 and 116 - are backbox lamps whose function is undetermined from the surviving documentation.** The A9 Auxiliary Lamp Driver parts list counts twelve SCRs and its harness wire list prints exactly eleven functions, all of which belong to other addresses, so exactly one of those five carries the twelfth output and the other four have no bulb. Nothing available says which: the A9 board schematic sheet is in none of the three retained manuals, the wire list leaves those pins unlabelled, neither retained script references them, the retained table parks three of them in a placeholder row and models no light for the other two, and the harness cannot discriminate because all sixteen auxiliary positions light together in the self-test lamp sequence - PinMAME reports matrix bits, not bulbs. Resolving it needs the A9 board sheet or a physical machine. That gap holds `output_enumeration`, `output_semantics` and `spatial_placement` open.

Centaur introduced `controllers/pinmame/by35.json`, the Bally MPU AS-2518-35 profile that every later BY35-driver machine should reuse. Its rules are: public momentary solenoid = PIA1:B selector + 1, so 1-15 with no address 16 because selector 15 is the idle state; four continuous outputs at 17-20; a six-column switch matrix published as sequential positions 1-48, not column-times-ten notation, with the three diagnostic contacts at -7 to -5; and a lamp strobe that ignores decoder selector value 0x0f and advances two matrix columns per data bit, so 16, 32, 48, 64, 80, 96, 112 and 128 are unreachable decoder slots rather than unused lamps. The public lamp address collapses to `16 * d + lampadr + 1` on the main board, plus 64 on the auxiliary board. A non-zero `lampCol` adds the second lamp board.

Three general lessons came out of this machine and are worth carrying to every other BY35 game. First, a manual's printed **"Self Test #"** column is a test *order*, not a public address, and the two are unrelated; the ROM's own solenoid test publishes the mapping because it flashes each coil's number as it fires it, so run it rather than guessing. For Centaur that exposed printed 14 and 15 transposed against public 14 and 15, and public 7 being the outhole kicker rather than the ball release both retained scripts call it. Second, on a six-column BY35 game one of the four continuous solenoid addresses carries the sixth switch-column strobe rather than a coil - on Centaur that is public 17 - and it reads as permanently asserted because by35.c OR-accumulates solenoid state within each VBLANK window, so never read a held continuous output as an unused one. Third, when mining a community table for geometry, check for rows of equally spaced lamps first: Centaur's retained table parks every auxiliary lamp its author could not place in a line along the bottom-left corner, and an earlier pass wrongly promoted those coordinates to validated placements.
