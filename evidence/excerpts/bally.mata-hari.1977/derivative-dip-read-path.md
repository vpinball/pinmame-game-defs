# Mata Hari DIP reads in the exact derivative ROMs

The audit reads the six authorized ZIPs in `L:/Visual Pinball/VPinMAME/roms`. It checks both members of each set against the CRC-32, SHA-1, and loader in PinMAME `46e1a01a0f73dc5ce163d98db1ae435883ecc450` (`src/wpc/by35games.c`, `by35.h`). The [ROM inventory](identity-and-roms.md) identifies the exact member pairs. Both V22 archives have the same program bytes. The reader uses the same pinned MC6800 opcode table as the [factory audit](stock-rom-read-path.md). It follows vectors and reviewed dispatch entries, scans every canonical ROM offset for possible direct or extended cache and PIA accesses, and records candidates and relevant indexed paths. The mirror carrying the CPU vectors is included in control-flow traversal. The listing marks offset scans that still need instruction alignment or reachability review. Unresolved indexed accesses limit the negative claims below.

From `review-artifacts/bally.mata-hari.1977/online-followup/`, replay with `python -B check-dip-consumers.py <authorized-ROM-root> <pinned-PinMAME-source>`. The reader and the resulting `derivative-dip-read-path.txt` have SHA-256 `99e5bd7199f2b36a2f354061bb6ebfdde4441de02526a432f150eac6cec67a01` and `592a8e3e6a2bd565e82dc11f2a4801ba0880772431c448cfe8977227acea42e8`, respectively. The listed addresses are CPU addresses in the selected loader map.

## Revision 7 first attract interval

The main loop at `$5b5d`–`$5b69` calls the attract handler through the ROM pointer at `$50d9`, which contains `$13aa`. The handler increments `$0e` at `$13b9`, compares it with `$b0` at `$13be`, then clears it and complements the A/B strobe byte at `$0203` at `$13c2`–`$13ca`. Setting S14 or S15 seeds `$0e` with `$20` or `$40`, shortening only that initial interval in the traced attract path. The same scratch region is reused for per-player state. The initial Start path calls `$1c7c` from `$5a9c` to clear RAM `$01`–`$16`, including the original DIP sample bytes. The later pointer setup at `$5f91`–`$5f9e` and accesses via `$2e` at `$19bf` and `$19d7` use those scratch bytes during play.

Four fresh, otherwise identical `matatest` runs changed S14, S15, or S22 individually, keeping the other bits at the baseline bank bytes `[00,00,18,00]`. The pinned DLL and runner conditions are the same as the [native follow-up](native-followup.md). The host sent no switch actions after startup. The fitted A and B lamps, 52 and 36, first rose at host time 8.500 s in all four traces. Both first fell at the rounded callback timestamps shown below.
