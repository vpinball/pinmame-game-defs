Source: the kpb105 ROM's own service menu, walked by `tools/harness-scenarios/capcom/kpb105-lamp-test.json` on fresh isolated state with pinned LibPinMAME (`pinmame64.dll`, SHA-256 `ca33d8fd92ff8f797db2628604db50ae02c8d6b95cd0d6718ce74833980d145d`, built from vpinball/pinmame `8371478a7640f1896dcdf565aed340dc5df989ba`) and ROM archive SHA-256 `fb64bcbc1dcd361ccc888cc235dde089e17907eac880af4cdfc3c7812269c0c5`. Raw run SHA-256 `d61d0fd4c85e068cee960c2647a597b8c0f762dc1863b6175932534a764edc99` (retained externally as `review-artifacts/kingpin/harness-runs/final-lamp-test/run.json` with every DMD frame).

Text is decoded from the 128x32 DMD frames by exact bitmap matching against the ROM's two fixed fonts (glyphs labelled from the ROM's own name strings, the rest by hand) and was checked by eye against the rendered frames; the companion image is a contact sheet of the decoded frames in table order. Wire colours and pins are what the ROM prints: its service code composes them from fixed colour tables, so they are the manufacturer's standard harness colour code for each position, not a harness trace.

Each row is one flipper step of the single-lamp test (the walk goes forward with the right flipper, then backward with the left; each position is taken from the first step that shows it); `Lit` lists the public PinMAME lamp addresses with a nonzero sampled state in that step, which can include the previous lamp still decaying. The ROM names lamps by matrix position (`CR` + bank: column C, row R, matrix A or B). In names, `(2)` and `(RED)` are the ROM's own annotations. While one of the three NOT USED positions is selected the ROM lights every matrix lamp, so those rows record all 128.
