# X-Men Pro V1.51 service-test readings

Two fresh, isolated xmn_151 runs used the pinned 46e1a01a LibPinMAME build, DLL SHA-256 8044e4dfbcd66dd2d686075f2b942d8c60c4a04899c603d2d67a9b2ff6103cd5. The user ROM member SHA-1 is db4339be7e9d47c46a13f95520dfe58da8450a19, matching the pinned driver. Only the archive/member names were normalized for the current driver; bytes were unchanged and the original library was not modified.

Every Single Lamp Test address 1-80 and every one of the 28 distinct Coil Test entries was read visually. Complete address/name/frame readings, pixel and artifact digests, raw-run hashes, and scenario hashes are in `tools/seeds/stern/x-men-pro-2012-service-readings.json`. This is the complete transcription region; blank matrix functions read NOT USED. The complete physical table and its electrical columns are separately transcribed in pro-lamps.md and pro-coils.md rather than inferred from the ROM.

Lamp 1 reads START BUTTON; 2 TOURNAMENT START BUTTON; 59 LEFT EJECT TOP; 63 NOT USED. The display's numbered lamp agrees with the same step's public lamp transition. Lamp 59 and 63 are different addresses, so a Pinside owner report about an unfitted head lamp at 63 does not settle 59. Lamps 28/29 read LIGHT LOCK (LEFT/RIGHT), where the Pro chart says CENTER TARGETS (LEFT/RIGHT). These are two names for the same insert pair. The script's descriptive Nightcrawler and medallion artwork labels are not moving toys or additional lamps.

The Coil Test prints LEFT SIDE (X2) at 17, RIGHT SIDE (X2) at 18, MAGNETO (LEFT/RIGHT) (X2) at 22, BACKPANEL (LEFT) (X3) at 28, BACKPANEL (RIGHT) (X3) at 29, MAGNETO SPOT LIGHT at 27 and MAGNETO FIGURE at 31. Each fired entry is paired with the public solenoid that actually changed, not its position in the menu. After 18 the selector proceeds to 21; it skips 19, 20, 23 and 30. Optional coil 24 is named but produced no observed transition; its fitment/activity is not inferred from absence.

These initial exploratory runs used the documented SAM menu recipe; all reached the actual named test and wrapped back to the beginning, verified on retained frames. `tools/xmen_pro_harness.py` and the pinned title-mask seed provide bounded DMD title checkpoints for fresh repeat runs, refusing unknown screens and other ROMs. Host key state is stimulus, never ROM switch evidence. ROM diagnostic counts corroborate the Pro physical chart; they do not turn a VPT glow into a socket or a trace's negative into non-fitment evidence.

Both checkpoint scenarios were then run successfully from separate empty state directories against the same exact driver/library: `lamp-checkpoint-repeat.json` (87 steps, 88 snapshots, SHA-256 d539a4fd86b5da6658a526826a08ce8d4edd8a8e189b1c502c64932d23b415ae) and `coil-checkpoint-repeat.json` (63 steps, 64 snapshots, SHA-256 5db3c614087305b5cd8650734adfb14c8a7723c50f4835083e016a481c255735). Every named menu checkpoint matched its own title before proceeding; neither repeat failed. Each completed a full selector cycle. The portable seed pins the exact committed scenarios and repeats. External-root checks verify their byte identities, driver/library, snapshot/step counts and all matched checkpoint titles.
