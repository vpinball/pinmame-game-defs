# ROM maps

Each file maps the firmware of one memory layout of one physical machine: game and mode state,
operator adjustments, audits, replay levels, sound commands, and recipes that start each mode from a
table script. This is supplemental knowledge. It never feeds a machine definition, and it does not
count toward `coverage`, `completion_score` or `author_ready`.

Path: `rom-maps/<manufacturer>/<machine-slug>.<map-id>.json`, where `map-id` is the PinMAME set
whose memory layout the file describes. `roms` lists every driver of the machine that shares it.
For each entry, its evidence records which ROMs it was actually verified on and, when narrower,
which ROMs it applies to.

## Format

A ROM map wraps a complete [Pinball Memory Maps](https://github.com/tomlogic/pinball-memory-maps)
document under `memory_map`. That part validates against the upstream schema vendored in
`_vendor/map.schema.json`, so it can be compared with, or contributed back to, that project without
conversion. Addresses are CPU addresses written as hex strings, as upstream does since file format
0.7. `extensions.addressing` records whether they also equal the raw `Controller.NVRAM` index.

What that format has no section for goes under `extensions`:

- `mode_state`: named game- and mode-state bytes, as upstream descriptors.
- `replay_levels`: the replay thresholds.
- `sound_commands`: the protocol, plus every command with its class, sample name and label.
- `mode_replay`: the ROM's switch timing, the running-mode word, and one recipe per mode with its
  precondition and its verification. The shape is adopted from the Attack From Mars mode-replay data.

`evidence` is keyed by JSON Pointer. An entry covers that descriptor and everything beneath it, and
`python -B -m pinmame_game_defs validate` fails when any descriptor, command or recipe is left
uncovered. Status uses the definitions' vocabulary: `candidate`, `observed`, `validated`,
`conflicted` or `deprecated`. Emulation alone never makes an entry `validated`.

The files are generated by `tools/curate_rom_maps.py` from the vendored maps and the pinned tables
in `tools/rom-map-inputs/`. Run it with `--check` to refuse drift.
